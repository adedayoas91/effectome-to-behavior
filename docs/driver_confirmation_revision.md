## Pre-confirmation diagnostic

The previous dense protocol requests 1,218,560 native window fits, rather than
only the 560 method/recording entries in its inventory. A reference-only audit
found inadequate direction-specific semantic alignment even when global
accuracy was high. The short-horizon future-disconnection effect was also far
below the fixed 0.10 positive-truth cutoff: most evaluated origins are late or
far from a transition opportunity. More repetitions cannot resolve this design
problem. Revised timing is chosen on development simulations, before fresh
confirmation, without using realized outcomes to select individual origins.

## Frozen scheduled protocol

Development seeds10/11 tested128 independent trials in each of the five scenarios.
The selected design has eight observed neurons (four population readouts), one
training-fitted PCA dimension, a256-sample history ending at303, and an8-sample
future target ending at335. Cue onset/offset remain288/480 within512-sample
trials. One half of the trials supplies held-out evaluation. Origins are fixed
by trial clock, never selected using realized transitions or effects.

Both development seeds supported every scenario/direction with semantic
agreement1.0,31–33 origins and16–24 events. Measured active-driver effects ranged
from about.535 to.744; redundant-pair effects from.548 to.750, with much smaller
individual redundant effects. These development checks used32 oracle rollouts;
confirmation retains256 rollouts and the original acceptance thresholds.
This establishes design eligibility, not successful graph attribution.

Confirmation uses positive seeds300–319 and null seeds400–459. The complete
inventory is140 recordings,560 method/recording runs and71,680 native window
fits. Independent method shards share the same event/reference/baseline hash;
each origin receives its own fresh upstream estimator. Conventional processes
reuse only package imports/JIT compilation. Raw graph decisions, upstream
evidence, package provenance and checksums are retained per method/recording.

Execution started under
`outputs/driver-validation/csl_sanity/scheduled-v2/confirmatory/`.
`frozen-protocol.json` is authoritative and source changes invalidate reuse.
The acceptance artifact distinguishes partial execution, ineligible evidence,
failed gates and passed gates. The four related variants never count as four
independent scientific replications. The observed process includes noisy latent
population readouts, so this is not asserted to be an ideal causal-sufficiency
control even outside the explicit hidden-confounder challenge.

## Numerical collection audit

The first merger bit-hashed fitted baseline outputs as well as common inputs.
Repeated equivalent logistic fits can differ by roughly2e-16. The reference
arrays, events and activity/history features were exactly repeatable; those
last bits must not redefine scientific sample identity.

`synthetic.verify_driver_collection` replays scoring from checksummed original
native graphs, never refitting discovery. Event/trial counts must match exactly;
scores, alignment and simulator effects must reproduce within absolute1e-10,
and paired baseline probabilities within1e-12. Original numerical scores and
native evidence are retained unchanged. The verified collection hashes exact
reference/event inputs, including baseline features and ownership, rather than
fitted solver last bits. Each recording retains a separate audit record.

The initial frozen source is archived in `implementation-snapshot.zip`. After
all560 entries have been verified and exported, the reviewed collection-only
source fix removes fitted output from the identity hash. A regression changes
only a baseline's last bits and verifies stable reference identity. The finalizer
runs the full tests, lint and types after applying that fix, and restores the
original source on verification failure. No estimator, scoring rule, simulation,
threshold or original result is changed by this numerical-identity correction.
